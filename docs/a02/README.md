# A02 LayoutProof design and reproduction

## Tensor and program contract

`Layout` describes a CPU FP32 view with a runtime-rank shape, signed element strides, a base offset, allocation capacity, storage identity and declared write capability. A nonempty coordinate maps to `offset + sum(index[k] * stride[k])`. Allocation bounds and signed arithmetic are checked. For any zero extent, the domain is empty and its origin may be one past the allocation. Rank zero has one coordinate. The FP32 restriction makes allocation sizes representable in bytes. The model stores metadata and provenance tokens and never dereferences a tensor pointer.

`Program` contains typed operations and a result-access request. Slice uses a normalized zero-based start, element count and nonzero signed step. Transpose swaps two axes, permute lists input axes in output order, expand inserts a singleton, and squeeze removes one. Broadcast aligns trailing axes and repeats missing or singleton dimensions. Reshape preserves the ordinal in its specified C or F traversal. A view reshape requires an affine address map on the target box in that traversal. This includes negative and zero strides where the target dimensions respect the input stride breaks. Explicit materialization permits any admitted source and uses an abstract fresh allocation slot identified by the operation index. Same-position materializations within alternatives use the same abstract slot. This is a single-result model with explicit live external peer views. Earlier intermediates never escape. Empty view operations preserve the input origin, and empty materialization uses a fresh slot with origin and capacity zero.

The comparison checks output domain, logical lineage (source coordinate in C order), value semantics (arbitrary FP32 bits at each source address), physical mapping, and access. Aliased source addresses may hold the same value token while their logical lineage differs. Physical equivalence includes output allocation identity even for empty outputs. Bytes of unused backing storage, allocator behavior and escaped intermediate identities are outside the model. Writable outputs require storage write capability, injectivity, and disjointness from every declared live peer on the same storage identity. Callers provide the full peer set and write-capability assumption. The model does not acquire a library borrow or prove storage lifetime.

## Decision paths

- The checked lowering computes affine view metadata and backward logical maps. Reshape lowering matches blocks of input and output axes in traversal order without crossing a stride break. The bounded interpreter forwards concrete cells and checks the address coefficients inferred from those cells. It uses exact address comparisons for aliasing. The two methods share checked arithmetic and a source-layout boundary.
- The default finite verifier cross-checks both paths and reports witnesses from the forward interpreter. The bounded replay path reconstructs the witness from checked layout metadata and backward maps. It checks the first mismatch in C order or first conflicting output pair. Domain mismatches and precondition failures have structural reason codes. Invalid-candidate replay checks definedness independently, so the error message may differ between the two paths.
- The symbolic producer composes signed permutations of axis descriptors. The separate replay module walks each output axis backwards through both programs and checks its source axis and reversal parity. Thus both programs select the same extents and functions, either `j` or `extent - 1 - j`. For a common valid source, the same coordinate map preserves source values and physical addresses. The same bijection preserves internal injectivity, intersections with live peers, and storage capability. A certificate requires matching access requests. Its result is conditional on the source layout and write preconditions. The certificate does not attest that an arbitrary caller satisfied them. It is in-memory replayable and its meaning is independent of numeric extents.
- The concrete-shape affine producer reads the checked lowering at the origin and at the unit coordinate on each nonsingleton axis. The separate checker validates shapes and pulls those coordinates back through each program with the independent interpreter's index equations. Each supported view transform is affine in its output coordinates. The probes fix every coefficient of the logical lineage and physical address maps, so the checker covers the whole box. It skips singleton directions, uses no probes for an empty box, and declines reshape. Equal maps preserve the same internal and peer intersections under the common access contract. The writable result is conditional on admissible source access and live peers. For matching output shapes, the first differing probe in C order is the first mismatching coordinate because earlier probes have fixed the origin and all lower-order coefficients. A failing result with a table carries the independently validated reference table for witness replay.
- `Checks(False, True)` disables address equivalence. It admits the explicit copy mutant. `Checks(True, False)` disables writable alias/capability checking. It admits the overlapping writable negative control. Both are diagnostic ablations. `verify(..., finite_only=True)` runs the interpreter without the lowering cross-check. `certify` is the symbolic-only path. `manual_double_flip` is a small manual baseline for one rule. The independent Momijo adapters are separate native baselines.
- The finite default cap is 256 cells per layout and stage. The allowed maximum is 4,096 cells, 64 axes, 64 steps and 16 peers. The symbolic normalizer supports at most rank 64 and 64 steps per program. A work limit is `UNKNOWN`. A differing symbolic normal form is `UNKNOWN` because a particular shape can collapse a difference. Other operations are outside the symbolic fragment and return `UNSUPPORTED`. No external solver is involved.

`PASS` is scoped to a concrete accepted decision or a replayed proof in the stated fragment. `REJECTED` denotes malformed input or an inadmissible reference. `FAIL` identifies a candidate mismatch or a failed cross-check. `ERROR` preserves unexpected internal replay/interpretation errors. The runner reports `NOT_RUN` when measurement admission is blocked.

Writable certificates report `CONDITIONAL_EQUIVALENCE`. Call `admit_symbolic_write` or `admit_affine_write` with the concrete source and complete live-peer snapshot before relying on the certificate for writable admission. These checks are bounded.

## Running the preflight

```sh
pixi run --locked research-a02 --help
pixi run --locked research-a02 --check-only --case copy-mutant --seed 42
pixi run --locked research-a02 --check-only --case affine-slice --seed 42
pixi run --locked research-a02 --output-root /path/to/orchestrator-managed/evidence
```

Help and check-only commands exit zero when the request returns its expected verdict. The runner replays a reported failure before accepting it as an expected mutant verdict. The measurement command exits 2 with `NOT_RUN` and creates no files. The supported preflight engine is `model` on CPU. Its affine case uses metadata for a billion-element logical input without allocating a backing tensor. General and Light run through `test-momijo` at the pinned library revision.
